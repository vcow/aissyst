# aissyst.desktop

Avalonia desktop application targeting .NET 10, with a startup wizard, a system log window, and an independent dialog window. It uses the Fluent theme and the system theme preference.

```sh
dotnet run --project aissyst.desktop/aissyst.desktop.csproj
```

`Program.cs` configures Avalonia and the classic desktop lifetime. The menus are **Aisyst**, **Interview**, and **Windows**. Aisyst contains Settings…, a separator, and Quit. Closing a working window hides it without stopping capture or discarding its contents. Windows → Log and Dialog are checkboxes synchronized with window visibility; reopening the Dock icon also shows the log. The Dock offers the same menu groups. Native menus are attached to every window; NativeMenuBar provides the fallback where native menus are unavailable.

Interview contains Force Dialog, Translate, Suggest, Answer, Translate & Answer, Translate & Suggest, a separator, Reconnect…, and Save Dialog…. Force Dialog finishes both pending audio fragments, pauses queue consumption while transcription and persistence complete, and displays the current conversation without an LLM request. Sources continue buffering during this pause; the 512-event channel and overflow warning are shared with the console. Repeated Force Dialog commands are ignored while one is pending. Reconnect… opens a modal, topmost **Are you sure?** confirmation with Yes/No. No, Escape, or closing the dialog does nothing. Yes cancels any active LLM request, reconnects, reloads the current conversation, and reinitializes the same session without rerunning setup. Concurrent reconnect attempts share recovery. Other windows and their commands are disabled during modal dialogs. Quit cancels pending commands and setup, stops audio, waits for transcription/persistence, disposes services, and exits.

Translate, Suggest, Answer, both combined commands, and Windows → Prompt are reserved and disabled until the prompt window is implemented. Force Dialog becomes available only after Start; Reconnect… becomes available when setup has completed. Save Dialog… remains available for exporting already processed history.

The application menu root is declared in `App.axaml`, so it exists during `App.Initialize`, before the macOS backend exports it in AppBuilder.AfterSetup. `DesktopApplicationShell` populates this same menu instance instead of replacing it later in OnFrameworkInitializationCompleted. Replacing the root at that point left the native exporter showing its original About Avalonia fallback. The existing native container receives the explicit Aisyst header. Dock export uses a separate menu instance.

The main window displays structured log entries in a virtualized ListBox on a dark gray background. Information messages are white, warnings yellow, and errors/critical messages red. Each entry retains its local timestamp, level, category, full message, and multiline exception details. Independent Info, Warning, and Error toggles are initially enabled; they hide entries without removing them. Error includes Critical. Selectable text inside each entry allows copying individual fragments.

Copy places a snapshot of the entire accumulated log on the clipboard, including messages hidden by filters and entries not yet rendered. Clear removes all stored, visible, and pending entries; subsequent messages continue to arrive and filter selections are preserved. There is no retention limit or automatic trimming, as requested. The log is held in memory until Clear or application exit. Updates from background loggers are collected into batches and dispatched to the UI, without rebuilding one large text string on every message. Formatting a full Copy snapshot runs in the background.

Automatic scrolling follows new entries while the view is at the bottom. Scrolling up pauses following, keeping the reading position stable as entries arrive. The Latest button appears while following is paused; it jumps directly to the last visible entry and resumes following. Manually scrolling back to the bottom also resumes following. The built-in ListBox scroll viewer and VirtualizingStackPanel are preserved.

`WindowLoggerProvider` implements `ILoggerProvider`; all application services receive their usual `ILogger<T>` from the desktop DI container and use this provider, including `ApplicationController`, Whisper, and the ChatGPT connector. The minimum level remains Information. The console uses its existing standard provider. Avalonia framework diagnostics still use `LogToTrace`.

`DesktopServices` registers the shared application controller, settings, SQLite store, text processor, Whisper transcriber, session model, and ChatGPT connector. The project does not depend on `aissyst.console`. `IApplicationSettings` remains the core contract. The console owns its original `ApplicationSettings` implementation; desktop owns a separate immutable `DesktopApplicationSettings` and settings store. The desktop project does not reference console. Console selectors, hotkeys, defaults, and standard logging provider are preserved.

Settings opens one modal dialog with four tabs covering every property in `IApplicationSettings`. Repeated menu requests activate the same dialog. Other application windows, including a wizard opened while Settings is already visible, are disabled until the dialog closes.

| Tab | Controls | Existing desktop defaults |
| --- | --- | --- |
| General | Audio-source dropdown; Markdown checkbox | Microphone and application; Markdown enabled |
| Recording | Numeric silence and maximum fragment duration in seconds; normalized signal threshold | 1 second; 15 seconds; 0.01 |
| Processing | Numeric queue capacity; two integer sliders from 1 to 5 | 10 fragments; 1 transcription task; 1 text task |
| Transcription | Model path with Browse, download URL, SHA-256, language code | Existing small.en-q5_1 path/URL/hash; en |

Save validates the whole form and atomically writes readable JSON to `LocalApplicationData/aissyst/desktop-settings.json`; on macOS this is under Application Support. An invalid form or failed write stays open with an error. Cancel or closing the dialog discards edits. Restore Defaults resets the form; Save is still required to persist the defaults. The current engine serializes Whisper inference internally even when the outer concurrency limit is higher.

**Settings take effect on the next application launch.** The dialog states this explicitly. Running services keep their immutable startup snapshot, avoiding inconsistent semaphore counts, model parameters, or source selection during a session. A malformed settings file is preserved, logged as a warning, and defaults are used until corrected through Settings. Desktop settings do not affect the console.

Window geometry and working-window visibility are service data, stored separately in `LocalApplicationData/aissyst/desktop-ui-state.json`. They are not part of `IApplicationSettings`, the Settings form, or Restore Defaults. The file records pixel X/Y positions for the log, dialog, wizard, and settings dialog, plus visibility for the log and dialog. Resizable windows also retain their normal client width and height in logical units. The fixed-size wizard retains its specified dimensions. Existing files without dimensions use the original window defaults; invalid dimensions are ignored without losing valid position or visibility data. Both working windows default to visible on the first launch. The required setup wizard always opens when a page is requested, and the modal Settings dialog opens only on request; neither restores a previous visible/hidden flag.

`DesktopWindowState` restores geometry before showing each window and tracks later moves, native resize events, and visibility changes. Disk writes are coalesced after 500 ms without changes and use atomic file replacement. Quit stops tracking before windows are programmatically closed, then DI disposal flushes the final state; shutdown does not turn previously visible windows into hidden windows for the next launch. Minimized/maximized or hidden geometry does not replace the last normal visible window geometry. Startup diagnostics record the state-file path and loaded working-window state without logging every move or resize. Invalid state files fall back to defaults with a warning; persistence errors are logged without preventing application shutdown.

The log, dialog, setup wizard, and Settings windows use `Topmost="True"` so they remain above ordinary windows of other applications. This sets their window level without adding repeated activation or focus requests.

The desktop lifetime remains OnExplicitShutdown without an automatically shown MainWindow. The shell controls startup visibility explicitly, which avoids briefly showing a log window that should remain hidden. Windows → Log/Dialog toggle their respective windows; Dock Reopen explicitly reveals the log.

**Windows → Fit to Screen** explicitly fits tracked windows, including hidden ones without showing them, into monitor working areas. The monitor containing the largest portion of the window is preferred; a fully off-screen window uses the nearest monitor. Position and client size account for display scaling and frame decorations; oversized resizable windows shrink while minimum dimensions and the fixed wizard size remain respected. Corrected geometry is persisted. Automatic fitting at startup and monitor-change handling remain deferred: saved coordinates are restored as-is until the command is used.

Startup follows the existing controller sequence:

1. Choose a saved session, or create one from an existing context or a ZIP template. Selecting a saved session shows Delete and Next (Open) on the same page; Create New shows the ordinary Next button. Delete requires inline confirmation, with Cancel returning to the existing choices without submitting a selection. Confirmed deletion removes that session and its dialog, then refreshes the list in the same window. Deleting the last session advances to context selection. Empty lists advance to context selection or template import. The file page supports a native file picker and an editable local path. Import errors appear on that page and in the log, allowing another attempt.
2. Sign in through the existing ChatGPT browser flow if necessary; choose an account-available model and its reasoning effort. Models without selectable levels use the server default.
3. Load Whisper, restore the selected dialog, and initialize the actual LLM session over the existing Responses connection.
4. Select a microphone and an application audio source. Either may be None, but at least one source must be selected. Selecting neither repeats source selection with an explanation.
5. Show a final Ready to start page with a short explanation and one Start button, without radio choices. No audio is captured while waiting.
6. Start audio capture only when Start is pressed, then close the wizard. The button disables during startup; a startup error leaves the same wizard open with an explanation and another Start attempt. Working windows were already opened or left hidden according to their saved visibility.

The context page likewise provides Delete and Next (Create) for saved contexts. Context deletion uses inline confirmation and refreshes the list; sessions already created from that context retain their copied data. Deleting the final context advances to template import. Create from Template uses the ordinary Next button.

`WizardService` implements the independent `IWizardService` UI contract. It creates one independent, nonmodal window on the first request, accepts requests from background threads, and serializes requests. The log and dialog windows are created before controller startup and shown immediately unless their saved visibility is hidden. Controller startup is queued independently of window Opened events, so setup still runs when both working windows are hidden. The wizard has a fixed size of 620 × 520 logical pixels, enforced by matching minimum/maximum dimensions and disabled resizing. The wizard restores its own position and no longer moves or resizes the log. Without a saved position it opens centered. Both windows remain interactive and movable. Radio choices have a vertical scrollbar. Next confirms only the current page and immediately disables until another page arrives; there is no Previous button.

The wizard uses border-only window decorations without active native close/minimize/maximize buttons. Drag the separate, permanent `aissyst - Setup` title bar to move it; the title bar remains enabled while a page is waiting or has failed. Normal close requests are rejected, including programmatic `Close()` outside its explicit completion method. The desktop startup code completes the wizard after controller initialization, explicit Start, and successful capture-worker startup; selectors do not need to know the last step. WizardPage supports a generic action page with a caption, description, and a single configurable button. Startup failure leaves the wizard open with an error and stops its waiting indicator. Closing the log window keeps setup running. Choosing Quit cancels initialization and disposes the wizard as part of application shutdown. Quit and restart the application to retry a startup failure.

Desktop and console share the SQLite location and ChatGPT credential store. Run one frontend at a time: the existing connector holds an exclusive credential-store lock. The Whisper model is downloaded into the desktop output directory if absent, so the first desktop startup may download it even if the console has its own copy. macOS is the supported audio platform; Windows enumeration/capture remains a placeholder and a startup error is logged there.

Startup progress reaches the wizard through an optional `IProgress<InitializationProgress>` in core and a desktop adapter; it does not parse logger messages. Downloads show a percentage and received/total decimal MB when Content-Length is known, or received MB and an indeterminate bar otherwise. Connecting to the download server, SHA-256 verification, native model loading, and LLM connection show their stage with an indeterminate bar. Download updates are throttled to about 200 ms, and the wizard keeps only the latest pending UI update. Page changes, failure, and completion discard queued progress from the previous page.

Normal logs retain download start, completion, cancellation, and failures, without periodic progress messages. Sanitized URLs, HTTP response metadata, timeout, and temporary paths remain available at Debug level. Errors preserve the exception and report the stage and bytes received. Download timeout settings, checksum verification, cleanup, and the model cache location are unchanged; automatic retry and resume are not added.

The independent Dialog window contains a virtualized ListBox on a dark blue background (#101E3A), with selectable wrapped text and no action buttons. Interviewer messages are white; interviewee messages are light blue and slightly indented. Vertical spacing, speaker labels, and local timestamps separate turns. The window opens immediately at startup unless previously hidden; setup completion does not force it to reappear. Closing it hides it without ending the application or losing history; Windows → Dialog reopens the same window. Its size and position can be adjusted independently of the log and conference window.

`DialogCoordinator.DialogUpdated` publishes the complete current history after initialization, each processed transcription fragment, and history reload, including the current unfinished turn. DesktopOutput forwards these snapshots to a shared DialogViewModel instead of writing transcripts into the system log. The existing console append output is preserved. GUI updates are coalesced onto the UI thread; a continued turn updates the existing item rather than appending the console delta as another message. History reload replaces the displayed history. New messages and extensions always scroll to the bottom, even after manual scrolling up. Scrolling remains available between updates. LLM suggestions do not become spoken dialog and remain routed to the log until the separate suggestion window is implemented.

The same Interview and Windows menus are installed for the log, dialog, wizard, settings, and confirmation windows; Aisyst is the native application menu on macOS and a fallback menu group elsewhere. Existing application-menu initialization preserves its early root instance. Save Dialog… uses the system save picker with a suggested .txt filename and writes plain UTF-8 without a BOM, with local timestamps, speaker labels, and blank lines between messages. It exports a snapshot of the complete processed dialog at the time of the command, including the unfinished turn and updates not yet rendered. It does not force audio transcription. Repeated save commands share the active operation. Cancelling the picker leaves the dialog unchanged; a failed save is logged and brings the log window forward. An existing file is truncated before writing so no suffix remains from a longer previous export. Shutdown cancels an outstanding save, closes the dialog, and releases a late picker result.

Desktop audio starts only through the final wizard page. `DesktopInterview` owns its lifetime, observes runtime capture failures, and drains remaining audio/transcription before controller disposal. The shared core `AudioCaptureSession` and `AudioRecorder` provide the existing console pipeline; the console CaptureSession remains a scoped wrapper with the same public API and hotkeys. The separate prompt window and its assistance commands remain future work.

Headless UI tests exercise window reuse, immediate Next disabling, cancellation, long-list scrolling, and DI/logging plus controller initialization with a test LLM connector. Selector tests cover SQLite session creation, template retry, model effort, and audio-source validation. Dialog tests cover restored/live history, unfinished-turn extension, reload/disposal, role styling, virtualization, unconditional scrolling on updates, menu actions, UTF-8 export, overwrite, cancellation, errors, and shutdown. These tests do not access credentials or send real LLM requests.
